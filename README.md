# LOGIC FOUNDRY — 논리회로 작업대

> 배포 단계 안내(2026-10-09): 로컬 검토 후 사용자의 공개 배포 승인을 받았습니다. 아래 LOCAL ONLY/NOT_RUN은 배포 전 검토 기록입니다. 승인 후 실제 공개 결과는 [통합 배포 검증](https://github.com/HyungminYoon1/web-lab/blob/main/docs/verification.md)의 최신 배포 절에서 따로 확인합니다.

[실행](https://hyungminyoon1.github.io/logic-foundry/) · [WEB LAB](https://hyungminyoon1.github.io/web-lab/)

게이트의 종류와 연결을 바꾸고, 입력 스위치와 진리표로 논리회로를 검증하는 작업대입니다.

## 직접 해보기

- AND·OR·XOR·NOT·NAND·NOR·XNOR, 과제별 8~24개 게이트
- 게이트별 입력과 최종 출력 연결, 실시간 신호·램프
- 입문부터 제약 도전까지 13개 과제, 최대 7입력·4출력·128개 조합의 전수 검증
- 출력 이름·비트 순서·대표 입력 사례, 첫 반례를 스위치에 적용, 불일치만 보기
- 단계별 개념/연결 힌트와 게이트 간결화 목표, 예시/초기 회로, 게이트 추가·삭제
- 회로도 게이트 클릭·키보드 선택, 실시간 노드 값과 배선 신호, 큰 회로 내부 스크롤
- 과제별 기기 저장·불러오기, JSON 가져오기·내보내기(16 KiB), 편집 되돌리기(최대 32회)
- 과제별 반례·신호 추적 과제: 올림 누락, 선택선·출력 교환, 패리티의 두 비트 오류와 불변 관계 비교

‘초기 회로’는 입력도 초기화합니다(첫 과제 A=0/B=1, 나머지는 모두 0). 편집 되돌리기로 직전 회로와 입력을 복구할 수 있습니다. 기기 기록 삭제가 실패하면 완료 기록과 갤러리 요약을 보존하고 실패를 표시합니다.

계정 없이 사용할 수 있습니다. 새로고침하면 편집기는 초기 회로로 시작하며 저장 회로는 직접 불러옵니다. 저장된 직접 해결 기록은 다시 검증해 표시합니다.

## 도전 과제

| 과제 | 핵심 설계 | 검증 조합 | 게이트 상한 / 간결화 목표 |
| --- | --- | ---: | ---: |
| 서로 다른 입력 램프 | DIFF, XOR 입문 | 4 | 12 / 1 |
| 반가산기 | SUM·CARRY를 독립 출력 | 4 | 12 / 2 |
| 다수결 | 세 쌍의 찬성 조건 결합 | 8 | 12 / 5 |
| 입장 조건 | 티켓 필수, 정지에 관리자 예외 | 8 | 12 / 3 |
| 전가산기 | A+B+Cin, SUM·Cout | 8 | 12 / 5 |
| 3비트 리플 가산기 | 두 3비트 수+Cin, S0·S1·S2·Cout | 128 | 24 / 15 |
| 2비트 가감산 유닛 | 모드에 따른 덧셈/뺄셈, 올림/빌림 FLAG | 32 | 24 / 13 |
| 4비트 패리티 검사 | 짝수 패리티 생성과 수신 오류 검사 | 32 | 12 / 4 |
| 활성 신호 주소 디코더 | EN=1일 때 Y0~Y3 중 한 출력만 선택 | 8 | 16 / 10 |
| 4채널 데이터 선택기 | 선택하지 않은 데이터의 영향 제거 | 64 | 20 / 11 |
| 2비트 크기 비교기 | GT·EQ·LT 중 정확히 하나 | 16 | 20 / 10 |
| 4요청 우선순위 중재기 | 가장 높은 활성 요청만 승인 | 16 | 16 / 8 |
| NAND 선택기 | NAND만 사용해 D0/D1 선택 | 8 | 8 / 4 |

숫자 입력·출력은 낮은 비트부터 표시합니다. 예를 들어 A=A0+2A1+4A2입니다. 가감산 결과는 0~3으로 순환하고, FLAG는 덧셈에서 올림, 뺄셈에서 빌림을 뜻합니다. 패리티는 짝수 개 비트 오류를 검출하지 못합니다. 조합논리만 다루며 클록·상태·전파 지연을 모사하지 않습니다.

앞쪽에 정의된 게이트만 참조할 수 있으며 순환·전방 참조·없는 입력·과제별 게이트/출력 제약 위반은 거절합니다. 상수와 입력을 출력에 직접 연결할 수도 있습니다. 대표 사례만 통과해도 정답은 아닙니다. 전체 진리표 통과가 필요합니다.

힌트와 과제 선택에는 잠금이 없습니다. 진리표 검증 버튼에서 전체 조합을 통과한 직접 해결 회로를 기기에 기록합니다. 예시·가져온 회로는 연습으로 표시되며 직접 해결에 포함하지 않습니다. 초기 회로로 시작하면 직접 도전할 수 있습니다. 간결화 목표는 달성 가능한 예시 기준이며 최소 개수가 아닙니다.

저장은 과제별 한 초안을 보관합니다. 직접 해결 기록은 검증된 회로를 보관하며, 갤러리에는 완료 개수·과제 수·실제 갱신 시각만 공유합니다. 저장 상한은 앱 데이터 128 KiB, 공통 요약 8 KiB입니다. 저장 데이터는 브라우저 저장소 삭제 또는 앱의 `저장 회로·완료 기록 삭제`까지 유지됩니다. 삭제는 이 앱의 기록과 공통 요약의 이 앱 항목만 제거하며 다운로드한 JSON과 현재 편집 중인 회로는 남습니다. 저장소 사용이 차단되거나 데이터가 손상되면 저장 실패를 표시합니다. 여러 탭의 동시 저장은 마지막 쓰기가 우선합니다.

JSON은 버전·과제·회로만 포함하며 완료 플래그를 허용하지 않습니다. 알 수 없는 키, 전방·순환·없는 참조, 과제별 상한 위반은 거절합니다. 되돌리기는 회로 편집·초기화·예시·가져오기·저장 불러오기에 적용되며 새로고침하면 사라집니다. 파일과 저장 데이터는 업로드되지 않습니다.

참고 개념: [원문과 추가 학습](https://docs.circuitverse.org/). 구현은 이 저장소의 계산 모델과 UI로 작성했습니다.

## 실행 및 검증

Node.js 22 이상. 외부 패키지는 없습니다.

```sh
npm run dev -- 0
npm test
npm run check
```

main에 푸시하면 검증 후 dist만 GitHub Pages에 배포합니다. 계산 모델·데이터 검증·저장 경계·UI는 분리되어 있습니다. 서버 업로드·계정·방문자 추적·공개 순위 기능은 없습니다. 호스팅 로그와 앱의 데이터 처리는 별개입니다.
